# 复杂案例演示数据与交互

日期：2026-09-27。用户明确要求增加模拟数据与复杂情况。全部新增内容为设计演示，不能用于产品注册、医疗判断或模型质量结论。

## 数据范围

| 内容 | 新增数量 | 关联方式 |
| --- | --- | --- |
| 项目资料 | 18 份 | 9 份核准状态演示、8 份待核验、1 份停用；包装方案含两个版本 |
| 资料集 | 3 个 | 多型号、软件变更、包装运输；每个资料集保留两个成员版本 |
| 文档任务 | 3 项 | 关联产品型号、软件变更或附件组合，分别呈现待审查、退回和待补资料 |
| 研究问题 | 每项任务 6 个 | 核验、冲突、待补证、版本变化、等待前置及已核验状态 |
| 能力与工具 | 2 项 Skill、2 项工具 | 保留待审核或待验证；没有演示发布成功 |
| 处理队列 | 4 条 | 正文可读、OCR 待核查；明确标记演示处理状态 |

当前初始合计为 32 份资料、7 项任务、3 个资料集。资料包含三页设计输入与验证证据册，其 PDF 和三张原页截图可打开查看。用户本次会话的新增资料另行计数。

## 可操作案例

| 情况 | 观察与操作 | 约束 |
| --- | --- | --- |
| 采样频率冲突 | 正文旁展开两项证据，定位性能指标章节，保存人工记录 | 500 Hz 和 250 Hz 均为演示取值；前置问题与证据未确认时不能标记已核验 |
| 扫描资料待核查 | 从资料概况进入处理队列与详情，查看 OCR 待核查及下一步 | 未执行真实 OCR，当前资料不能核准 |
| 包装版本变化 | 查看包装方案历史版本、运输记录与影响问题 | 历史引用保留固定版本 |
| 专业角色依赖 | 协作分区查看字段核验、章节撰写、来源审查与总稿的前置关系 | 演示状态不代表远端执行 |
| Gru 介入 | 从问题进入对话，发送要求，确认登记为待处理输入 | 关联原问题、章节与文稿版本，不自动更改正文 |
| 成果检查 | 正文旁展开章节、导出与再次下载 | 图文稿导出自包含 HTML，图片和来源固定；文本任务使用 Markdown；正式 DOCX/PDF 服务未接入 |

数据定义位于 `complex-demo.js` 与 `registration-dossier.js`。复杂主案例为八个章节的产品描述与型号配置文稿，初始 19 项引用，包含三项图表原页。申请清单按六类组织 38 个官方二级节点。工作台提供“进入复杂案例”，直接地址使用 `?revision=registration-evidence&scenario=complex#human-review`。

真实公开资料使用独立入口及 `public-reference.js`，首次打开增加一个公开参考项目、一项任务与三份资料；未打开时保持 12 个项目、7 项任务与 32 份资料，打开后分别为 13、8、35。新增来源均待核准，图像来自官方原件，FDA 产品字段仅用于独立参考。字段定义和来源范围见 `prd-v13-field-check.md`。

`check-continuous-workspace.mjs` 验证演示流程的界面行为，不将演示状态作为真实后台结果。原有文件读取测试继续使用工作区实际文件。页面刷新恢复演示初始状态。
