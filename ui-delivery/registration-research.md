## 申请资料的组织

| 类别 | 资料要求中的主要内容 | 人工核查动作 |
| --- | --- | --- |
| 监管信息 | 目录、申请表、术语缩写、产品列表、关联文件、沟通记录、符合性声明 | 确认申请人、产品名称、分类、注册路径、申报型号与声明一致 |
| 综述资料 | 概述、产品描述、适用范围、上市历史及其他说明 | 核对工作原理、结构组成、软件、接口、连接关系、型号差异与禁忌证 |
| 非临床资料 | 风险、基本原则清单、适用标准、技术要求、检验报告、研究资料、稳定性、其他资料 | 对每项适用要求登记验证方法、证据位置与结论；根据产品确认电气、软件、网络安全、生物学、灭菌等研究的适用性 |
| 临床评价资料 | 临床评价路径及证据、临床试验资料及其他内容 | 确认具体产品评价路径、差异论证和证据充分性；通用模板不决定免于临床评价或试验 |
| 说明书与标签 | 说明书、标签样稿、其他产品信息 | 核对预期用途、型号、警示、性能及使用条件，与相关申请文件逐项比较 |
| 质量管理体系 | 体系综述、生产制造、文件控制、职责资源、产品实现、测量改进及核查文件 | 确认程序文件、流程图、场地和设备清单、体系核查材料与项目实际情况 |

页面设置六类 **38 个官方二级目录节点**，各类数量分别为 7、6、8、3、4、10；质量体系 6.1 为综述，6.2 为章节目录。每项默认“待确认”；选择“不适用”必须填写决定依据和责任人。一个申请项可以关联多份固定版本资料，一份资料也可以支持多个申请项。具体内容由 11 个文档类型、57 个初始字段组维护，见 [字段核对](./prd-v13-field-check.md)。

申报格式要求包含资料组织、页码和跨文件一致性等要求；电子申报应采用相应系统要求。原型 HTML 图文导出用于设计验证，不能直接视为正式申报文件。

## 产品技术要求与研究文件

产品技术要求目录为：产品名称、型号规格及划分、性能指标、检验方法、术语（如适用）、附录（如适用）。性能指标与检验方法编号需要对应，引用标准需要说明编号及年代号。成品指标应可客观判定，研究性、评价性内容通过独立研究文件维护。

产品描述与型号配置是另一份申请资料。当前复杂案例以八个章节展示产品概述、组成、性能特征、检验对应、软件、型号差异、包装版本影响和适用范围。正式申报采用经人工确认的产品适用目录；不能把演示章节直接用作批准模板。

## 正文、图片和原件的关系

每项引用保存文件标识、名称、版本、原文位置、原文摘要、引用类型、页码、图注及核对状态。原页截图还保存图片路径。点击正文证据可以查看完整原页，进入资料中心的固定版本，再返回对应章节。

演示证据册包含三页：型号配置表、验证条件核查、软件界面样稿。PDF 与三张 PNG 由同一 HTML 原件生成，文件校验摘要保存在 `assets/evidence/provenance.json`。这些内容均有“设计演示”标识，不能替代客户原件、设备截图或检测报告。

正文图文导出使用自包含 HTML，图片采用内嵌数据，保留版本、页码、图注及核对状态。导出记录固定当时内容，可重复下载。来源更新、引用编辑或正文修订需要重新核查；未核查引用、待核准资料及版本变化会阻止当前文稿的审查确认。
