# IMP-23 / RV-06 人工重新定位前端

## 范围与产品规则

2026-10-18 用户确认：每次人工重新定位成功后变为 OPEN（待处理），保留原始批注意见、原始引用、回复、处理记录与每次位置历史。实现使用独立 `annotation-anchors` / `reanchors` 扩展，不声称替代原冻结 RV-06 Record 合约，也不包含文档确认、签署或完整 IMP-23。

当前正文的普通讨论面板读取有效位置投影；原批注 `document_revision`、Selection、制品、摘要、内容、作者和时间保持原值。有效位置独立展示。原版本面板保留原始意见，回复及决定读取返回的有效固定版本通过独立快照核验。跨版本位置面板明确区分原始引用、当前有效引用、最后有效引用和需要重新定位。

待重新定位且有效位置仍属于旧正文的批注，当前界面可读历史，但必须先重新定位到当前已保存正文，再回复或处理。此为当前严格禁止历史新写入的边界，不能称为完整原始审查工作流。

## 人工操作及权限

用户必须在完整已保存正文阅读器手动选择文字、图片或表格单元格，点击“使用当前选区作为新位置”，填写原因，并显式勾选确认。改变原因或选区会清除确认。没有自动相似文本匹配。Selection 复用现有 Unicode code-point、图片与表格校验。

新写入要求 `annotation.read` 与 `review.decide`，原始/旧有效/新目标来源分别核验；当前未签发、非历史、无未保存编辑，且文稿头、批注修订、有效锚点身份与指针修订均匹配。服务端负责真实 `DOCUMENT_REVIEW` 来源授权及事务内重检；客户端校验不是服务端许可替代物。

原始与有效 Selection 分别读取对应固定正文，核验完整正文 schema/template/hash 和 Selection，绝不将当前正文当作历史引用证据。生命周期要求从批注修订 1 的 OPEN 起，连续核验每一项 DECISION、REPLY、INVALIDATE、REANCHOR；人工决定须逐项对应 DECISION，不能通过删除最终状态检查来掩盖失效/重新定位事件。

## 不确定结果与恢复

独立操作名 `RV-06-REANCHOR-1`；恢复记录只存身份、原 CAS、固定正文摘要及请求摘要。理由、Selection、批注内容、正文和凭据不进入 web storage。原输入只在标签页内存保存；刷新后必须重建完全相同的请求，不匹配输入不能覆盖原请求。

停止等待、上下文失效和页面切换终止后续异步派发；共享写锁覆盖准备、提交、原操作核验、完整读回及保留编辑的父级刷新。未决重新定位与原批注写入互斥。历史/签发/脏正文恢复只有 FOUND 的原操作可重放，NOT_FOUND、EXPIRED 或 FAILED 不创建替代请求。

先核验原回执的 OPEN、原版本/CAS/作者/原因/选区/水位及完整摘要，再核验完成操作、当前投影和不可变位置历史中的原锚点。后续再次定位、回复或解决不会使旧回执冒充当前状态；成功回执与当前状态独立显示。
