# 074 运行记录保存策略

普通入口 `/agents/retention` 提供企业/项目策略列表、固定详情、新增、明确替换和停止使用。界面使用实际项目目录；分类与原业务合同一致：PUBLIC、INTERNAL、RESTRICTED、PERSONAL_HEALTH。没有自创 CONFIDENTIAL 映射。

## 策略和原请求

固定策略明确运行记录与事件流的保存期限、备份到期、清除方式和生效区间。批准、替换和停止使用均要求当前实际权限，修改表单后必须再次确认。替换/停用使用原修订 CAS，原政策及决定不可变，审计和事件独立绑定完整私有授权证据。执行消费者重新核当前唯一有效政策、原批准人的有效身份及原批准授权；多份有效政策不能随意选最新一份。

列表是有界实时 keyset，不提供虚假全量总数。当前列表访问和运行消费属于不同用途；看到策略不代表可以批准或执行。默认服务关闭，启用时须明确候选容量，超限失败，不静默截断。

## 未知结果与取消

浏览器发写前保存完整原请求。超时或 NOT_FOUND 时只读恢复，不清空原 key，也不自动重发原写。

用户可以明确请求撤回尚未登记的原命令。撤回使用独立 key，并原子保存完整原请求与撤回请求。服务端在既有企业事务锁下串行处理：

- 原命令已登记：返回 COMPLETED 和真实原回执，不撤销已完成政策。
- 尚未登记：保存不可变 CANCELLED 标记，后到的原命令不得再次登记。
- 撤回未知或未查到：继续保留双方请求与 key。只有经核验的取消/完成回执并保存证据后，才允许关闭该条待处理记录。

这不是删除既有政策、修改历史、物理擦除或放宽当前权限。真实数据清除 worker 与存储保留 enforcement 不由该治理页面代替。
