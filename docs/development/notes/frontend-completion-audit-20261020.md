## 最小且诚实的前端优先下一片

建议在现有 task-detail/document-editor 上做“撰写与核验工作区信息架构”，不新造假后端：
1. 复用现有组件，保持连续正文优先；辅助区统一目录、字段/证据入口、当前任务缺项及真实运行信息。
2. 清晰区分已保存正文、待确认编辑、固定证据已读取、技术检查结果、专业检查未接入；不要设置本地已核验/已审查/已签发状态。
3. N03–N07 导航可先展示职责、已有入口和具体缺项，但无服务结果时显示“未提供”，不以阶段顺序推导完成率或成功状态。
4. 维持现有保存/比较/退回/导出 API 与权限保护；新增定位/筛选是纯前端，可先完成。缺真实候选和检查 DTO 的操作禁用并说明原因，而非伪造返回。
5. 验收此片：已有正文编辑/读写路由可达、dirty 不丢失、审查只读、历史与当前版本不混淆、未授权不预读、空态/失败态/键盘/窄屏验证。通过只能称该片完成，不能称全前端完成。

然后才按契约推进：N03 结果/确认 → N04 候选与采用 → N05/N06/N07 专业检查/总稿 → RV-07/08/09 → 正式交付。UI 外壳可以前置，但真实状态与持久动作必须等待实际后端能力。
