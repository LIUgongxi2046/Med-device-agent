- RN01 prepares physical published086 evidence outside SQL transactions, then revalidates the same task/input/request and current078 policy, literal ROLE permissions, retention and dependencies inside acceptance. Original-key receipt recovery does not demand new physical preparation.
- RuntimeReplayAssembler assembles the existing published replay schema from actual fixed task/snapshot/confirmed plan, template/profile/budget, policy/model identities, publication evidence, source rights and complete registry lineage. Unknown provider reexecution is not presented as exact replay.
- Additive093 explicitly separates independently approved task-owned delegation from immutable literal ROLE v1. Rules pin release approval, ROLE/policy hashes, project, purposes/actions/model/artifact kinds, validity and budget ceilings. No actual approval record is created by this checkpoint. REPLAY_MANIFEST registration is a separate private singleton capability, never a generic node token permission.
- FormalRunControlAccess authenticates actual mTLS and the persisted START_RUN on each short transaction. Original-read capability is callback/thread/transaction-bound, version/hash-pinned, read-only and not a human session. Source SESSION ownership is denied. Original083/084 and expert evidence dependencies include genuine verified source-rights revisions separately from lineage.
- Live release audience/scope/role invitation checks remain independent of publication/policy/delegation. A separate exact START_RUN scope proof requires the current task.run/RUN_CREATION grant, while the control check separately requires task.run/TASK_EXECUTION.
- Additive092/094 run-owned intent, attempt, registration and governance evidence remove the false requirement to fabricate a leased step before the replay exists. Actual physical transfer uses the existing object transport with fresh current content/source/lineage authority for every PUT/recovery GET segment. Registration verifies exact versioned readback, access manifest, full governance graph, lineage, audit and outbox.
- Registration and bootstrap do not manufacture a step, lease, token, RUNNING state, successful professional result or workflow acceptance. The durable launch primitive pins explicit deployment configuration and command identity, commits intent/attempt before transport, verifies real Temporal acknowledgment or original history, and records acceptance. Existing attempts are query-only. Terminal receipt recovery uses a separate current mTLS/read capability, never new execution authority. These production boundaries are implemented but remain unwired and have only synthetic transport/SQL tests here.
