# 089：正式评测原始输入对象登记

状态：已集成代码，尚未部署。此能力只完成固定 N01 输入对象的登记，不表示专业 Agent 或正式评测全流程已完成。

## 输入、权限和归属

服务读取实际 083 原始执行记录、088 已批准上下文以及 079 原资料，执行现有 DOCUMENT_ONLY 编译器与固定 tokenizer。调用方不能提供编译结果、任意对象引用、token 数或审批标志。

当前操作者必须具有实际 EVALUATION 对象上的 artifact.register / EVALUATION_RESULTS 权限。原 N01 ROLE 还必须明确包含对应 PROJECT 上同动作、同用途的权限；这使 ROLE 能在评测 UUID 生成前正常编写，且不改变通用 ROLE 的精确匹配规则。evaluation.run、原资料读取、模型发送等既有权限仍独立核验。

完整原始授权、ROLE、上下文、编译器和资料依赖证据保留在不可变意图中，并在对象写入前及最终登记前重新核验。代码不创建授权或专业审批。

产物归属实际 EVALUATION，run_id 和 document_revision 为空。没有借用 TASK、SYSTEM_JOB 或模型验证作业来假装正式评测运行。

## 写入与恢复

- 单独的原请求键和完整正文，绑定操作者、上下文、评测执行、样本、重复轮次及 N01 节点。
- 原始意图与单次物理尝试先持久化，再在事务外进行对象 I/O。
- 首次写入期限为原始意图创建后的五分钟，不随重试延长。
- 已有尝试或不确定结果只能读取同一对象恢复，不能再次 PUT、换键或伪造回执。
- 最终登记消费真实传输层私有证明，核对对象版本、字节、摘要、大小、依赖清单、审计及 outbox。
- 完成后的再次请求仍重新验证当前权限；登记回执不能直接当成执行证明。

## 部署顺序

必须先应用 089 迁移，再部署共享 ArtifactRegistry 读取保护。所有通用产物读取都会查询 089 所有权表；缺表时失败，不会降级绕过检查。改名或修改资源绑定也不能使 089 产物进入通用读取路径。

迁移新增三张不可变业务表：formal_evaluation_exact_input_intent、formal_evaluation_exact_input_attempt、formal_evaluation_exact_input_registered。每表保留独立企业、项目、操作者、时间、分级及 schema 元数据。完整表清单为 284 张业务表、321 张总表。075—088 原始迁移未修改。

## 验证与边界

已执行真实 Java 方法级、权限、恢复、对象传输适配器、SQL 结构及兼容性测试；数据库存储和对象存储在离线测试中使用明确的替身。SQL 测试夹具保留生产源码摘要及真实方法生成记录，支持与新 JVM 输出逐字节比对。集成验证发现 Map.of 的迭代顺序会影响 SQL 字段顺序，现统一排序字段并同步绑定对应值，避免跨 JVM 证据不稳定。
