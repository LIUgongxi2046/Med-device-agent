# Formal verification adapter transport

Deployment is disabled by default and requires both `medical.model-runtime.enabled` and `medical.formal-invocation.enabled`, actual approved credentials/configuration, private durable storage, actual mTLS identities, source/S3 configuration, a fixed executable tokenizer and explicit bounds. This slice supports MODEL_VERIFICATION with PROJECT model owner equal to the actual request project. It does not provide ordinary TASK invocation admission.

Internal requests require a current service certificate before reading body bytes, one X-Schema-Version: 1.0.0 header, no query, and at most 16 MiB. IN08 and IN09 additionally require one real X-Run-Token header. The local formal-invocation-http schema defines request bodies; original public ModelResult and RequestParameters remain strict downstream gates.

- POST /internal/v1/invocations: Reserve. Exact worker action/model/context/parameters are checked against the real job before reserving both actual budget accounts.
- POST /internal/v1/invocations/{id}/begin-send: BeginSend. The original dispatch attempt is immutable. Only its first live admission consumes the private permit and returns fixed provider bytes. A repeated request returns new_send_admission=false with no private provider/configuration fields. This is not a reusable authorization token. The Python adapter additionally uses the shared durable dispatch guard before any upstream call.
- POST /internal/v1/invocations/{id}/receipts: Receipt. Exact original ModelResult and reversible provider CaptureArtifact are validated, written/recovered through immutable object intents and actual private transport proofs, registered, and accounted. The original adapter identity can report facts after user lease expiry; it cannot create another send.
- POST /internal/v1/invocations/{id}/reconciliations: Unknown. Only TRANSPORT_OUTCOME_UNKNOWN and original tenant/actor/attempt identity are accepted. It records an unresolved factual observation against the real dispatch/audit chain, retains all reservations, and supplies no usage/price or invented provider receipt. There is no supported trusted provider-statement reconciliation producer in this slice.

Application cancellation requires the real authenticated session/context, original owner and current model.verify grant. POST /api/formal-invocation-cancellations accepts Cancel with a full ASCII original Idempotency-Key header. GET /api/formal-invocation-cancellation-operations uses the same header and performs read-only original-key recovery. It returns found plus nullable original receipt. Before dispatch, actual reservations are released and actual job/step cancelled. After dispatch, a stop request does not prove provider termination and releases no unknown charges.

Unknown outcomes do not enable replay. Complete originals retained in the private durable receipt journal can retry IN10 across process restarts. Missing originals remain unresolved. See RECEIPT-RECOVERY.md.

Verification boundaries: isolated Java tests use real validators/services with SQL and permission boundaries doubled; no database migration, live S3 or paid model operation was executed. Python filesystem recovery is actually exercised across processes. Original SDK fixture bytes came from actual OpenAI SDK with MockTransport.

## Actual worker entry

The three additional exact mTLS POST routes are `/internal/v1/model-verification-workers/claim`, `/issue`, and `/status`. Claim takes only schema_version + tenant_id and performs a bounded live scan of real MODEL_VERIFICATION jobs assigned to that service. It derives actor/run/step/revision from the stored job and calls actual RunTokenAuthority.claimStep. Issue takes schema_version + tenant_id + verification_id, requires the actual current service-owned lease, and calls actual RunTokenAuthority.issue with the original principal's exact action set. It returns the issued token, original worker action, model/context and request parameters. Status is a service-bound factual read; it creates neither a new token nor provider send. The HTTP filter is stateless, with no browser-session fallback.

Deployment entry: `python -m medical_model_gateway.formal_verification_worker --config /absolute/private/deployment.json [--once]`. The existing private configuration contains the tenant, API origin, existing CA/client-certificate/private-key paths, approved credential binding file, existing common durable directory, byte/time caps and polling interval. It creates no credentials/directories/grants. It performs claim → issue → reserve → begin-send → real provider stream → durable originals → IN10. Thus no user constructs a lease, action or token. On uncertainty the process stops with a content-free error; the supervisor reviews the original operation, never repeats its send. `--recover-manifest receipt-<original-attempt>-manifest.json` selects an existing private durable original and retries only IN10. This cannot restore response bytes lost before durable publication.

worker-lease-seconds is an additional explicit 2..300 deployment bound, capped by actual run-token policy. A currently owned lease can issue a token only within its remaining lifetime. An expired unsent job without an invocation may be reclaimed through the real generation/CAS authority. A reserved invocation is not reassigned to another lease; its original cancellation/recovery path remains necessary.

This worker code does not eliminate the separate first-user preparation gap: 085 must produce the genuine project EXACT_INPUT and scope snapshot before a first verification can be submitted. Existing arbitrary IDs or SIM artifacts are not substitutes.

All successful responses use the published InterfaceProtocol.Envelope (`resource_revision`, never `revision`) and exact X-Request-Id/X-Schema-Version/no-store headers. Cancellation receipt is immutable revision 1; absent original-key recovery returns null resource_revision, found=false and receipt=null. CancelReceipt and CancelRecovery are independently closed local schema definitions.
