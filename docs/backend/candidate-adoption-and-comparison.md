# B03: actual candidate reads, physical comparison, explicit adoption

The implemented path is:

1. A completed N06 stage is read through its immutable original journal and four complete physically recovered artifacts. The human reader rechecks current task, artifact and source permissions, not expired producer execution permission. Currently authorized colleagues may read, compare, preview and explicitly adopt; historical task creator identities remain exact factual journal pins, never substituted for the current human admission. Read-only physical transfers are attributed to that actual current reader. Execution authorization is unchanged.
2. `POST /api/runs/{id}/document-candidates` materializes exactly one stable aggregate candidate. It does not save a document, consume consent, reopen a task, or invoke N07.
3. BX07 `GET /api/candidates/{id}` returns the existing typed `CandidateView`. Original evidence points to the actual base `DOCUMENT_EVIDENCE`; new evidence points to the actual candidate `DOCUMENT_BODY`, whose evidence is at `/evidence_links`. Its ArtifactRef retains the actual DOCUMENT_BODY schema, never a fabricated evidence schema.
4. BX08 `POST /api/candidate-comparisons` consumes the existing `CandidateCompareRequest` and returns typed `Comparison`. A separate candidate structural schema preserves candidate identity; it never casts the candidate UUID as a document revision. The bounded structural engine uses both real complete bodies. An immutable physical difference object is written/read back once, registered with current source dependencies, and audited. Retry and `GET /api/candidate-comparisons/{id}` perform original-only recovery and verify exact input/output bytes. An obsolete requested target returns a conflict.
5. `POST /api/candidates/{id}/adoption-previews` creates an immutable 10-minute pending action. INITIAL requires the exact registered blank scaffold; SELECTED_NODES replaces only authorized non-overlapping existing subtrees. Unselected nodes and fields are retained. Candidate, actual baseline/head, selected scope, full merged bytes, current authority and source evidence are digest-bound.
6. DC03 `POST /api/candidates/{id}/adoptions` requires the authenticated user's explicit confirmation of the pending action/digest/revision. No generated output or professional check substitutes for this action. Real body/field/evidence objects are transferred outside SQL transactions. Fresh short-transaction proofs are rebuilt from immutable physical originals, not reused old admissions.
7. One final transaction registers normalized content and true provenance, CASes the unchanged head, writes adoption and the user's decision, consumes the pending action, invalidates old checks/reviews/anchors, completes the original DC03 operation, and emits exactly one genuine CHECK_DOCUMENT intent. N07 is a separate SYSTEM_JOB and cannot turn candidate PASS into body PASS or human professional approval.

Source dependency roots and provenance are intentionally separate. Output artifact access manifests contain the complete verified source graph with non-null rights. The new document revision also records actual baseline, N06 and N04 artifact provenance edges, allowing N07 to exclude every writer session from independent verification.
