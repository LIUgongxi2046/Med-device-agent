# Pure fixed-document comparison core (staging)

This directory contains only a bounded deterministic algorithm, its closed local `CoreResult` schema, and offline tests. It is not BX-05 production comparison, an ArtifactRef, a persisted receipt, a current permission proof or a professional assessment. Existing published CompareRequest and Comparison remain unchanged. No producer, storage, HTTP route, database table, grant or migration is added here.

## API

`DocumentStructuralComparisonEngine.compare(InterfaceProtocol.CompareRequest, DocumentBody left, DocumentBody right, Limits)` accepts complete typed bodies. The caller must later prove that both bodies belong to the same real document and the exact requested saved revisions, using actual source-aware fixed readers. A pure algorithm cannot establish those database associations. Both bodies are validated with the real frozen DocumentBody schema and DocumentBodySemantics before comparison.

`CoreResult` binds the exact published request, both canonical body hashes, frozen body schema digest, local schema digest, actual implementation bytecode digests and explicit limits. It includes all records, unchanged records included. Every record retains canonical JSON before/after and corresponding SHA256. This intentionally has no fake comparison ID, artifact identity, currentness, approval, or readiness field. The persistence layer must wrap it in a separately verified real registration and artifact.

## Exact matching and completeness

- Stable node, field, evidence-link and cell IDs are matched exactly. Image/formula metadata remains complete in node records; no resource bytes or semantic equivalence is inferred.
- Every top-level array order and table row/column/cell order is explicitly retained. Node parent and ordinal changes appear in full node snapshots. Array order is not silently normalized away.
- Table Cell has no inline value field in the frozen contract. Its actual cell ID, row/column IDs, spans and ordered node IDs are preserved; content values are the separately compared real referenced nodes.
- FactUsage has no unique usage ID and can legally repeat a fact_version_id for distinct node/field associations. FACT records therefore group complete original-order usages by exact fact version; the global ORDER record keeps repeated version IDs. Version replacement is removed/added, while changed associations within one version are changed. No invented stable fact lineage.
- Text uses Unicode code points and a single exact replacement range bounded by the longest common prefix and suffix. This is deterministic and linear, not a minimal edit script. Original whitespace and combining marks are never normalized. Both half-open selections include the actual quote and UTF-8 quote SHA256. Unchanged text has an empty replacement at its end. Mark changes remain visible in node snapshots.
- Affected node IDs include changed node identities and true field/evidence/fact associations. Affected sections follow each side's real ancestor tree, including deleted left-side sections. Check/review/signature references require real repository records and are intentionally absent from this pure core.

## Bounds

Every caller must supply positive nodes, cells, relationships, input bytes per side, complete output bytes, record count, combined text-code-point budget, deterministic work budget and elapsed milliseconds (at most one day). The real body validator enforces graph/reference/table constraints. Before entering DocumentBodySemantics, typed input nodes and total actual cells are bounded, and each table prepays n*(n-1)/2 rectangle-overlap work. Explicit work charging also bounds ancestor traversal and field-association resolution. Each emitted record charges its actual canonical UTF-8 size plus separators before it is appended; the final metadata envelope is separately charged, so the engine does not accumulate an oversized record list and only then notice the result limit. Capacity/time exhaustion throws CONTEXT_LIMIT with no successful partial result. The time limit is cooperative checkpoint checking, not a hard interrupt or CPU sandbox: a single frozen-schema/semantic-validation/canonicalization call cannot be interrupted mid-call. Production must supply conservative finite input/node/cell/byte/work limits; the prepaid overlap bound controls its known quadratic table loop. At most one separately bounded input/record serialization may be in progress between checkpoints. Text budget includes added and removed text nodes. No clinical thresholds, default credentials, model execution or automatic merging are present.

The closed local result schema verifies digest/count/coverage consistency, exact canonical snippets, frozen node/field/evidence/fact/cell shapes and original code-point quote selections. Schema.validate is only shape/digest self-consistency and must never establish source completeness. The mandatory engine.verifyAgainstInputs(request,left,right,candidate,registeredLimits) entry fully recomputes from the two actual authenticated fixed inputs and compares the entire canonical result, including every record identity, all three affected-ID lists, side hashes and coverage. Invoke it immediately before producer registration and after typed-reader object verification. The request and registered limits must come from the real immutable registration, not from candidate JSON. A digest is not a signature or permission. Coverage selection is the complete input identity hash; delivered is the actual complete ordered record hash.

## Integration boundary

Do not publish these files to production until the two-sided current authorization, immutable input association, full dependency union, real object intent/unknown-write recovery, artifact registration and readback, operation/audit/outbox, typed read/pagination and frontend contracts are separately implemented and reviewed. No full comparison-business or real MySQL/S3 claim follows from offline algorithm tests.
