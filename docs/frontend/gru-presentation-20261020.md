# Gru 固定文稿助手：前端呈现

## 已实施

- 保留现有 `document-gru-records.vue` 的会话 API、保存、原请求键、未知结果恢复、过期证明导出、权限及可见性清理逻辑。
- 固定上下文卡显示项目、文稿、正文版本；未保存正文明确阻止会话写入。
- 可选 `savedBody` 仅用于已保存正文的选区预览。文字按 Unicode code point 截取；版本不匹配、正文缺失和图片/表格分别显示明确说明，不伪造原文。`dirty=true` 时无条件隐藏正文选区预览。
- 会话历史空态只在真实列表读取完成后显示；保留显式读取、分页和固定数据水位。
- 用户记录采用独立消息气泡，显示用途、保存时间、固定选区信息及记录身份，并始终标注“已保存 · 未执行”。
- 输入区呈现未提交草稿、缺少权限、未保存正文、旧版本会话等状态。用途标签中文化；缺少消息或理由时禁用保存按钮。
- 执行和采纳入口明确禁用并标注未接入/无候选，不发出模型请求，不把用户消息呈现为助手回复。

## 契约边界

现有 `GruRead` 只接受 `USER` 消息、`NOT_EXECUTED` 状态、空 `candidate_ids` 和空 `run_id`。本次没有扩展生产 API 或 Schema，没有模拟回复或虚构候选。PRD §8.4.1 的执行、建议确认卡、候选采纳必须等待真实运行与候选契约接入，不能仅凭前端展示声称实现。

## 集成

父组件继续传入固定 `snapshot`、当前会话、`active`、`dirty` 和 `selection`。仅当已验证保存基线可用且正文无未保存编辑时传入 `savedBody`；无该属性时显示真实选区节点和位置元数据。

## 临时离开与输入保留（2026-10-20）

同一身份、上下文和固定文稿的临时关闭、历史查看及浏览器隐藏仅保留尚未提交的输入和所选会话身份；读取内容、选区绑定和恢复确认均清理，返回后需显式重新读取会话，不自动发消息。隐藏、非活动、全局会话失效或读取权限撤销时不渲染私有内容。真实身份、会话、上下文/授权、文稿版本变化清理草稿；全局失效及“放弃未提交草稿”后不会通过旧的恢复归档重新填回输入。原未知写入键和服务端核查流程保持不变。

回归包括 49 个 Gru 检查以及实际父子导出集成测试；导出测试的 Store 夹具明确提供当前认证会话。预览 Store 与组件传入会话通过相同原始对象身份核查。
