# FE-26 导出历史分页与实际核验信息

日期：2026-10-18。对应 `remaining-frontend-20261018.md` 第 0 节第 1、4 项。范围仅为 `document-export.vue`、`api/medical/exports.ts` 以及独立测试；不改后端、路由、签发或核验制品读取资格。

## 实际交互

- 历史使用现有 `GET /api/documents/{documentId}/exports` 的 `document_revision/page/size`，每页 20 项，不全量扫描。
- 显示服务器返回的 page、total 和 has_more；分页按页码限制 1–1000000、size 1–50 校验。API 核对分页回显、文稿身份、固定版本、重复 export_id、每页数量和 has_more/total 一致性。
- 翻页开始即清理旧历史行、当前导出详情、重试理由和原下载 Object URL。新页读取成功后由用户明确选择一条记录。查询失败没有旧记录可执行，显示重读提示；“刷新本页”继续同一页。上一页允许从已失效的空页返回。
- 身份/文稿/固定版本变化沿用原同步清理；分页请求使用 generation、AbortSignal、活动状态和会话对象核对，迟到结果不能回填。
- 当前记录刷新只更新本页中相同 export_id。新建或恢复不在本页的导出仍可显示其独立详情，但不会伪插入服务端分页；页面提示刷新本页，原 total 不在客户端虚增。
- 已有 validation 字段直接展开：核验格式、输入/计划/文件摘要、文件字节、转换器和字体版本、渠道状态、版面状态、已核验节点完整列表。空列表明示，无分母不推算全文覆盖率，NOT_RUN 显示未执行。
- `validation_artifact_id` 仅显示标识，不生成普通 Artifact 链接，不承诺下载该核验制品。固定导出输入独立展示模板、审查清单、格式、渠道和导出清单版本/摘要。

## 保留的写入与下载边界

EX-01 创建、EX-04 重试、原请求恢复及文件下载函数在页面和 API 中保持原实现；原 key、元数据恢复、服务端许可、固定输入核对、下载字节数/SHA-256 检查继续有效。翻页与刷新历史属于只读动作，在写入进行中禁用。既有执行机制未扩展，不新增自动重试。
